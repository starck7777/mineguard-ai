# Render deployment

## Architecture

```text
Browser → Render FastAPI web service ─┬─ React/Vite static build
                                    ├─ REST API
                                    ├─ WebSocket live stream
                                    └─ Render PostgreSQL
```

The root `render.yaml` Blueprint is the production source of truth. One public
origin serves the UI, API and WebSocket, so no public API URL or CORS variable
is required. SQLite remains local-development-only.

## Deploy

1. Open the repository's **Deploy to Render** button.
2. Sign in to Render and authorize the public GitHub repository if requested.
3. Review and apply the Blueprint.
4. Wait for `mineguard-ai-db` and `mineguard-ai` to become available.
5. Open `https://mineguard-ai-rpzc.onrender.com`.

The Blueprint uses Singapore, a free web service and free PostgreSQL. Render's
free PostgreSQL databases expire after 30 days and have no backups; upgrade the
database before relying on persisted production data. Free web services also
spin down when idle and can take time to wake.

## Verification

Check the following after deployment:

```text
GET /health
GET /api/public/status
GET /api/nodes
GET /module-analytics
GET /device-coverage
GET /hardware-model-3d
WSS /ws/live
```

The backend initializes tables and fictional demonstration data idempotently.
`MINEGUARD_ADMIN_TOKEN` is generated by Render and should be read only from the
service environment when authenticated placement editing is needed.

## Redeployment and rollback

Pushes to `main` automatically rebuild the service. Use the Render deployment
history to redeploy a known commit. Database rollback requires a paid database
with backups or an external backup process.
